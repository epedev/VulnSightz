# Vulnerable Target App

A deliberately vulnerable Flask application for **authorized, local web-security training** and testing the companion `webvuln-scanner` project. It provides a small set of routes with known security flaws so a crawler and scanner can be tested against a predictable target.

> **Safety:** This application intentionally contains exploitable vulnerabilities, including OS command injection. Run it only on your own machine or inside an isolated lab. Do not expose it to a public network, deploy it to production, or use the test techniques against systems without explicit authorization.

## Features

- Flask application with a SQLite database.
- Simple login, search, comments, profile, admin, and ping pages.
- Recon endpoints at `/robots.txt` and `/sitemap.xml`.
- Seed data for repeatable testing.
- Intentional vulnerabilities documented in [`VULNERABILITIES.md`](VULNERABILITIES.md).
- Lightweight CSS in `static/style.css`.

## Requirements

- Python 3.10 or newer (a currently supported Python version is recommended).
- `venv` support for Python.
- Dependencies listed in `requirements.txt` (currently Flask).

## Installation and run

Run these commands from the directory containing `app.py`.

### Bash / Zsh

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python init_db.py
python app.py
```

### Fish shell

If your terminal is Fish, use its activation script instead:

```fish
python3 -m venv venv
source venv/bin/activate.fish
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python init_db.py
python app.py
```

You can also avoid shell activation entirely:

```bash
python3 -m venv venv
./venv/bin/python -m pip install -r requirements.txt
./venv/bin/python init_db.py
./venv/bin/python app.py
```

The app listens on `http://127.0.0.1:5000`. Keep the host bound to localhost. If the operating system reports an `externally-managed-environment` error, check that the virtual environment was created successfully and use `./venv/bin/python -m pip ...`; do not use `sudo pip` or bypass the system package protection.

## Test accounts

These are intentionally weak demo credentials, not real accounts.

| Username | Password | Intended role |
| --- | --- | --- |
| `alice` | `alice123` | Standard user |
| `bob` | `bobpass` | Standard user |
| `admin` | `SuperSecret99!` | Administrator |

The initialization script drops and recreates the app's tables. **Running `python init_db.py` again deletes current comments and resets all seeded data.** Stop the app first if you want a clean reset.

## Routes

| Route | Purpose | Security issue intentionally demonstrated |
| --- | --- | --- |
| `/` | Home page | Session display |
| `/login` | Login form | SQL injection (CWE-89) |
| `/logout` | Clear the current session | Session handling demo |
| `/search?q=...` | Search article titles | Reflected XSS (CWE-79) |
| `/comments` | View and submit comments | Stored XSS (CWE-79) |
| `/profile/<id>` | View a user profile | IDOR / authorization bypass (CWE-639) |
| `/admin` | List user records | Broken access control (CWE-284/285) |
| `/ping` | Run a ping diagnostic | OS command injection (CWE-78) |
| `/robots.txt` | Crawler hints | Recon information |
| `/sitemap.xml` | Endpoint list for crawlers | Recon information |

For the detailed root cause, impact, detection ideas, and remediation guidance, see [`VULNERABILITIES.md`](VULNERABILITIES.md). For project layout and a suggested testing workflow, see [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) and [`docs/TESTING.md`](docs/TESTING.md).

## Project structure

```text
vulnerable-target-app/
├── app.py                  # Flask routes and intentionally vulnerable logic
├── init_db.py              # Creates/resets SQLite tables and seed data
├── requirements.txt        # Python dependencies
├── target.db               # Generated at initialization; do not commit real data
├── static/
│   └── style.css           # Page styling
├── templates/              # Jinja2 HTML templates
├── docs/
│   ├── ARCHITECTURE.md     # Components and request flow
│   └── TESTING.md          # Local setup and validation workflow
├── README.md
└── VULNERABILITIES.md      # Security findings and remediation notes
```

`target.db` is generated by `init_db.py`; it may not exist until initialization. Keep generated databases and virtual environments out of version control.

## Scope and limitations

This is a training target, not a production application or a complete security benchmark. Findings are deliberately planted, and the vulnerable patterns should not be copied into real projects. The app uses plaintext seed passwords and a fixed Flask secret key by design; those are part of the exercise, not recommended practices.
